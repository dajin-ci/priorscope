# Studio Compare Agent 문구 (판정 기준 확정, 2026-11-02)

판정 기준의 원본은 `verdict_rules.py` 다. 자세한 기준은 Compare_Input.pdf 안내문에 모두 들어가고,
Studio 에는 1000바이트 제한 때문에 그 안내를 따르라는 요약만 넣는다. 문구를 바꾸면 `python verdict_rules.py` 로
바이트 수와 함께 출력해서 붙여 넣는다 (1000바이트를 넘으면 tests/test_verdict_rules.py 가 실패한다).

## 실제로 연결된 노드

`pipelineEdges` 기준으로 Parse → 지시-1(Instruct) → Extract 하나만 연결돼 있다. 설정 파일에 남아 있는
`Extract_Low`, `Extract_Medium` 스키마와 Classify 설정은 초기 설계(Classify → Extract ×3)의 흔적으로 실행되지 않는다.
Classify 설명의 "기존 논문의 모델을 도구로 사용만 하면 Low" 는 확정 기준(그대로 쓰면 일치)과 반대이므로,
다시 연결하기 전에 반드시 고치거나 Studio 에서 지운다.

## 1. Extract 노드: element_mapping 원소(items) 설명 (577 bytes)

```
M마다 한 줄: M2 ↔ P4,P5 | 유사 | M[3.1] / P[2.3] | 설명
대응 없음: M3 ↔ - | 없음 | 검토 범위 P1~Pn | 설명
판정은 문서 안내의 판정 기준을 따른다. 요약:
일치=기존 P를 그대로 씀(사전학습 모델·임베딩 공간 포함)
유사=같은 역할로 방식만 변형·교체
없음=기존에 없음. P 제거, 학습 규모·설정값만 변경, 범용 기법만 공통도 없음. P칸은 -, 설명에 관련 P
확인필요=판단이 안 서면 없음 대신 쓴다
다른 용어·언어로 쓴 같은 기술도 대응으로 본다
```

## 2. 지시-1 노드: 지시문 (787 bytes)

```
입력은 내 논문(M, R-M)과 기존 논문(P, R-P) 비교 자료다. 문서의 번호만 쓴다.
1) M마다 대응을 쓴다: M2 ↔ P4,P5 | 유사 | M[3.1] / P[2.3] | 이유. 없으면 M3 ↔ - | 없음 | 검토 범위 P1~Pn | 이유. 판정은 문서 안내의 기준을 따른다. 핵심: 심사자가 '기존 논문에 이미 있다'고 반박할 수 있으면 일치·유사, 아니면 없음. 확신 없으면 확인필요.
2) 데이터셋·지표가 같은 실험 쌍: R-M1 ~ R-P2 | 동일 조건 또는 조건 다름 | 이유
3) 1)의 판정으로 등급을 정한다. High Overlap: 핵심 요소 대부분이 이미 있음. Medium Overlap: 일부 겹치나 고유 구성 있음. Low Overlap: 분야만 비슷함. 등급과 이유를 M 번호를 들어 2~3문장으로 쓴다.
```

## 3. 저장 후

설정을 내보내 `agent_configs/Compare Agent.json` 을 교체하고, `.env` 의 `COMPARE_CONFIG_ID` 를 새 버전 번호로 바꾼다.
