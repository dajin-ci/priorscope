# Studio Compare Agent 문구 (판정 기준 확정, 2026-11-02)

판정 기준의 원본은 `verdict_rules.py` 다. 이 파일은 Studio 에 붙여 넣을 문구를 모아 둔 것이며,
`verdict_rules.py` 를 바꾸면 `python -c "import verdict_rules; print(verdict_rules.rule_lines())"` 로 확인해 함께 고친다.

## 1. Extract 노드 3개 모두: element_mapping 의 원소(items) 설명

세 스키마(High·Medium·Low 분기)의 `element_mapping` 원소 설명을 아래로 바꾼다. 세 곳이 글자까지 같아야 한다.

```
M 요소마다 한 줄. 형식: M2 ↔ P4,P5 | 유사 | M[3.1] / P[2.3] | 설명
대응 없으면: M3 ↔ - | 없음 | 검토 범위 P1~Pn | 설명
판정은 일치·유사·없음·확인필요 중 하나.
판정 기준은 '이 M을 기존 논문과 다른 점이라고 주장하면 심사자가 기존 논문에 이미 있다고 반박할 수 있는가'다.
일치: 기존 P를 그대로 쓰거나 같은 기법이다. 기존 논문의 사전학습 모델·인코더·임베딩 공간을 그대로 쓰는 경우도 일치다.
유사: 기존 P와 같은 역할을 유지한 채 방식을 변형·확장·교체했다. 예: 정적 마스킹을 동적 마스킹으로, WordPiece를 BPE로.
없음: 기존 논문에 없는 요소다. 기존 P를 제거한 것, 학습 규모·기간·배치·데이터 양 같은 설정값만 바꾼 것도 없음이다. 이때 P 칸은 '-'로 두고 설명에 관련 P 번호를 적는다.
없음: Transformer 사용, 손실 함수로 학습처럼 범용 기법 수준의 공통점만 있으면 없음이다.
확인필요: 위 기준으로도 판단이 서지 않으면 없음이 아니라 확인필요로 적는다.
같은 기술을 다른 용어나 다른 언어(국문/영문)로 쓴 경우도 대응으로 본다.
```

## 2. Instruct 노드 지시문

```
입력 문서는 내 논문(M, R-M)과 기존 논문(P, R-P) 비교 자료다. 문서의 번호만 쓴다.
1) M마다 한 줄씩 대응을 쓴다: M2 ↔ P4,P5 | 유사 | M[3.1] / P[2.3] | 이유. 대응 없으면 M3 ↔ - | 없음 | 검토 범위 P1~Pn | 이유. 판정은 일치·유사·없음·확인필요.
   판정 기준: 심사자가 '기존 논문에 이미 있다'고 반박할 수 있으면 일치·유사, 아니면 없음. 기존 요소를 그대로 쓰면 일치, 같은 역할로 방식만 변형·교체하면 유사, 기존 요소를 제거했거나 학습 규모·설정값만 바꿨으면 없음(설명에 관련 P 번호). 범용 기법만 같으면 없음. 확신 없으면 확인필요.
2) 데이터셋·지표가 같은 실험 쌍을 R-M1 ~ R-P2 | 동일 조건 또는 조건 다름 | 이유 로 쓴다.
3) 1)의 판정을 근거로 등급을 정한다. High Overlap: 핵심 요소 대부분이 이미 있음. Medium Overlap: 일부 겹치나 고유 구성 있음. Low Overlap: 분야만 비슷함. 등급과 이유를 M 번호를 들어 2~3문장으로 쓴다.
```

## 3. 저장 후

설정을 내보내 `agent_configs/Compare Agent.json` 을 교체하고, 버전이 올라갔으면 `.env` 의 `COMPARE_CONFIG_ID` 를 새 버전 번호로 바꾼다.
